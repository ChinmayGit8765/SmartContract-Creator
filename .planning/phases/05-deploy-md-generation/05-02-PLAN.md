## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| DeployMeta → rendered Markdown | The contract name + constructor example values flow into copy-pasteable commands and the doc body. The contract name is user-supplied (already validated by Phase 2/4 validators; an invalid identifier would have failed compile-verify before deployMeta runs). |
| rendered doc → disk (later, in 05-03) | The doc is a Markdown artifact written alongside the .sol. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-01 | Information Disclosure | section renderers (private-key / address placeholders) | mitigate | All secrets are placeholders (`<YOUR_PRIVATE_KEY>`, `<YOUR_WALLET_ADDRESS>`, `<KEY>`); generate.spec.ts greps rendered output for `0x`-hex addresses and fails if any appear. |
| T-05-04 | Tampering (markdown injection) | header/warnings/constructor-args sections that echo meta.contractName | mitigate | meta.contractName is the wizard-validated Solidity identifier (already constrained to a valid `contract X` name by compile-verify; the filename derivation strips non-alnum). No untrusted free-text (RPC URLs, addresses) is interpolated as raw values — all are fixed placeholder tokens, not user input. The doc reflects only the validated name + the tool's own placeholder strings. |
| T-05-03 | Repudiation / trust | warnings section | mitigate | Renders meta.warnings (the DEPLOY-06 single source from 05-01); the golden fixtures lock the disclosed risk set per option combo. |
| T-05-SC | Tampering | npm/pip/cargo installs | n/a | Phase 5 installs ZERO new packages. No install task. |
</threat_model>
