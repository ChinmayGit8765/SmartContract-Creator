<objective>
Add `smartc add-feature` — a local-AI patch flow. It reads an existing generated
contract, asks a local Ollama model for the full updated file, previews a diff,
confirms, sandbox-compiles the result, and only writes on a clean compile
(otherwise the file is rolled back). Graceful when the daemon is down.

Purpose: the opt-in AI customization from PROJECT scope, gated on the existing
compile-verify safety net (the diff + sandbox-compile + confirm make it safe).
</objective>

<design>
- src/ai/ollama.ts: injectable-fetch HTTP client (isOllamaReachable, generateCompletion), resolveOllamaHost/Model, DEFAULT_OLLAMA_MODEL, ollamaUnreachableError. Network failures → CliError(E_AI_UNREACHABLE) pointing to doctor + ollama.com.
- src/ai/prompt.ts: buildPatchPrompt (return the COMPLETE file), extractSource (strip code fences).
- src/ai/diff.ts: LCS line diff + colored unified-style preview (no external dep).
- src/commands/add-feature.ts: refuse --json; require --ai + --file; infer chain from ext (.sol/.rs); reachability check (AI-05); generate (AI-02/06); diff + confirm (AI-04); sandbox compileVerify before write (AI-03 rollback = never write on failure); solana-without-anchor skip is applied-with-warning.
- errors.ts: E_AI_UNREACHABLE, E_AI_EMPTY. program.ts registers the command.
</design>

<verification>
- tsc clean; full suite green.
- Live (no daemon): `add-feature --ai --file f.sol "x"` with an unreachable host → E_AI_UNREACHABLE exit 1.
- E2E mocks the ollama module (reachable/generate) + @clack confirm; real solc verifies the AI output; broken output is rolled back.
- Note: a real Ollama daemon is absent in this environment, so the live generate path is exercised via mocks; the user must install Ollama to run it for real.
</verification>
